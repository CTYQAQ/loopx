# RFC：持久化 Goal 成果细化（v0）

- 状态：实现提案；安装／模型采用与比较收益尚未取得资格。
- 归属：Core Goal 验收与工作规划（S3/R4），调用方为 S1/S5。
- 英文镜像：[English](goal-outcome-refinement-v0.md)。
- 既有合同：[共享 Goal 对齐](shared-goal-alignment-and-governed-amendment-v0.zh-CN.md)。

## 问题与当前证据

重要交付物可能只是一条宽泛长期 Todo 中的一句话。用户后续纠正推动了单轮修改，
却没有保留完整的累积要求。例如调整演示顺序时，可能意外删掉已认可的开场。
完成 Todo、发布候选版本或切换工作，都不能证明交付物满足累积意图。
这里使用泛化复现；私人对话和运行状态不进入本文或测试数据。

既有机制解决的是相邻问题：

- Todo 管理执行、认领、租约与完成；宽泛长期任务不能标识其中每项独立成果。
- Agent Vision 是有界的当前路线与检查点，不是所有承诺成果及累积要求的持久目录。
- Governed Goal amendment 保留原始承诺，目前可执行的类型主要实例化所有者
  授权的工作模板；普通细化不是任意新模板，也不是新增权限。
- Goal acceptance 管理检查命令、任务关联和当前证据。准备检查不等于采用，
  局部检查通过不等于整个 Goal 完成。方向材料提供来源版本，不管理工作归属。

## 设计决定

在既有 canonical Goal authority 内加入结构化的支撑成果，由验收归属管理。
每项成果有稳定 ID、负责 Agent、原始目的、累积条件 ID／描述、已存在的 Todo
关联和有界来源引用。这是规划声明与默认有据自查，不是独立 Goal、调度器、能力、独立验收结论或权限。

原始 Goal 及根承诺保持原样。细化操作不能覆盖成果最初的目的，也不能改写已有
条件描述；只能增加条件和工作关联，并保留来源及操作回执。矛盾纠正必须显式
协调；v0 不把只增细化冒充为一般替代机制或受治理的根意图修改。

只有需要独立负责人、预算、生命周期或执行边界时才拆为独立子 Goal。
重要性本身不要求另开运行实例。跨轮次、任务或反复纠正、且有独立结果与条件的
工作适合登记成果；普通消息、维护动作和中间步骤不应全部升级为成果。

## 普通用户消息

绑定 Goal 的 Agent 根据真实宿主上下文，区分直接人类请求、心跳、引用文档、
工具结果和同伴消息。不能靠关键词推断用户权限或重要性。推进重要新成果或
实质纠正前，复用内联成果上下文（缺失时才查询）、细化对应条目，再经正常 Todo 操作关联工作。
保留旧要求并记录最新来源；没有可靠宿主消息 ID 时使用稳定的本地不透明证据
引用，不伪造已核验发送者来源。

来源标签只表示归因，不证明认证或授权。身份和范围仍由宿主管理；注册 Agent
只能细化自己负责的成果。根目标修改、权限扩张、发布和可执行检查保留既有
授权。已有范围内授权下，记录细化不应引入重复确认。缺少重要意图时，先在对话
中澄清真正影响结果的选择。

外部宿主升级后通过 CLI／技能桥接使用；这不是普遍的消息拦截钩子，宿主投递
与 Agent 遵循仍需分别验证。App、飞书通过桥接复用原生归属，不另建解析器和状态文件。

## 状态、读取与恢复

复用已提升的 canonical authority、writer fence、provider CAS、追加操作日志与
既有 Goal 生命周期校验。来源失败不能回退到 Markdown。稳定操作 ID 恢复丢失
响应；冲突重试、过期版本、其他 Goal 实例与其他 Agent 修改必须拒绝。
升级本身不会给既有 Goal 自动添加成果或改变调度。

即使关闭可执行检查，验收读回也包含已声明成果。默认目标维护与有据自查没有
启用开关。旧 `enabled` 字段只控制已配置的检查命令，不能关闭要求、自查或缺口
投影。细化不能提交独立检查通过的证据、执行命令或修改 Goal 生命周期。

在有意义的交付／实验节点，Agent 对照全部累计要求检查产物，以 `met`、`unmet`
或 `uncertain` 记录结论、理由和证据引用。默认自查可结清未配置检查的规划缺口，
但必须与独立验证、用户认可分别呈现。已配置条件不能被自查绕过，仍由匹配的当前
检查与工作覆盖提供结果。Todo 完成不能代替任何一种结论。

自查绑定累计要求及关联工作的声明；这些变化会使依据过期。证据引用是 Agent
陈述，v0 不解析或计算所引产物的指纹，因此产物修改后必须重新核对。保留引用
不能证明时效或质量。

既有准入工作上下文携带完整成果声明；内联内容完整时，无需额外查询验收。
变化可合并到普通 `refresh-state --goal-outcome-update-json`，或一次原生
`refine_outcome` 调用。无变化不额外调用、不增加往返，也不重复登记自查。
这里是顺序组合：先提交细化，再做普通写回。后续写回失败时，返回的细化回执
标明已提交部分；按原操作重试，不能假定全部回滚。

| 节点 | 默认动作 | 联动机制 |
| --- | --- | --- |
| 直接用户消息带来重要成果／实质纠正 | 细化对应成果并保留旧意图 | 宿主上下文＋原生细化或技能／CLI |
| 恢复、切换工作、replan | 复用全部要求再选择工作 | 共享工作上下文；缺少来源时才必读 |
| 有意义的产物／实验节点 | 用实际证据核对全部要求 | 一次细化，可并入普通写回 |
| 要求未满足／未自查，且没有关联的活动／等待工作 | 传递类型化规划缺口 | 现有 frontier replan；其他可执行推进优先 |
| 没有相关变化 | 继续执行，不增加协议交互 | 既有准入与写回 |

关联的 open／blocked／deferred Todo 保持原有归属和等待规则。新增成果缺口
不能抢占其他可执行工作。Replan 使用证据决定下一项有用工作，或说明继续现有
路线的理由；缺口、自查都不强制改方向。不新增调度器、定期审计、配额扣减或
由子成果触发的根目标停止。

## 简化默认路径

新编写路径不设 Goal acceptance 启用开关。成果要求、里程碑证据自查和无工作覆盖时
的重规划始终可用。旧持久化/传输字段 `enabled` 只兼容已配置的命令检查；修改其默认值
会恢复原先停用的命令和完成约束。日常展示直接说明要求、自查和已配置检查，不再显示
“Goal acceptance 未启用”。

更新已有成果只需 ID、来源和本次变化字段。类型化 owner 解析不可改写的原始目标、
负责 Agent 及保留的要求/工作；创建时仍须明确目标和负责 Agent。因此里程碑自查可随
已有写回提交，无需重复这些声明。

可执行检查接受 `{outcome_id, criteria: [{id, validation_argv, ...}]}`。类型化 owner
从该成果解析要求描述、目标和关联工作。待采用方案展示解析快照及命令；采用时再次解析，
要求或工作变化后在执行前拒绝。快照仅服务审阅，不成为第二份要求权威。保留独立旧检查
文档的兼容性，不增加隐式命令执行、权限或根目标完成判定。

## 开放式研究与避免早停

支撑成果从属于原始研究目标。局部假设的自查、一次实验成功、所有局部要求满足
或短期平台期，都不能代替根目标的继续、预算和停止条件。本改动不写入
`achieved`、`no_followup`、预算或终态。原有合法停止和等待条件仍然有效，
既不强制耗尽预算，也不编造填充任务。存在有用且已授权的研究时，未解决要求
可以保留不确定结论并继续推进。

后续 EdgeBench 资格遵循[现有测量合同](long-horizon-harness-benchmark-research-program-v0.zh-CN.md)：
对齐任务、模型／推理、来源及检查点、评分器、反馈可见性和总预算。保留后期／
共同窗口比较，以及有效、无效、缺失的区别。比较任务原生最终／最佳成果、完整
模型／工具／CLI 成本、耗时、人工介入、剩余预算原因和提前终结／宿主冲突率。
计入协议上下文与自查成本，局部分数更好不能掩盖最终效果下降或早停。研究中只
使用求解方可见证据，隐藏评估只在允许的终结阶段使用。本 RFC 不启动或修改实验。

验收目标是效果与完整成本效率至少不低于基线，并且没有早停回归。确定性续行
一致性只是前置证据，不能证明真实模型不劣。模型实际采用、产物质量和匹配
benchmark 收益仍需后续验证。

## 产品路径与交付切片

Agent 从用户请求准备并登记成果，不让用户重填 JSON。Goal 概览在方向与验收旁
显示成果原始目的、累积要求、负责 Agent 和工作。所有者可原地追加要求并读取
原生结果。过期写入或服务不可用显示恢复路径，不盲目重试。CLI 与前端复用同一
类型化归属，不需要新配置编辑器或 capability ID；provider 为既有本地 canonical
 authority，属于内置 Core。

先提交此设计，再交付原生细化、必读投影、未解决覆盖保留、CLI、既有 Goal UI、
外部宿主技能指导、反例与打包后端读回。本切片不升级当前安装、不改其他对话的
实际工作、不合并 PR，也不发起付费模型实验。

## 成本与有界重构

Heartbeat 规则新增 523 个字符，旧条款全部保留。同一受支持的范围 fixture 中，
compact 指导从 7,286 增至 7,809 字符（含原 Reward Memory 额度），普通 thin
从 3,147 增至 3,670。展示回归上限调整为 compact 7,200、thin 3,700，独立的
640 字符额度保持。这是实际上下文成本，不是效率收益结论，也不是运行预算扩张。
无变化工作不增加 Agent CLI 交互，但有成果的上下文仍增加读取／投影与 token
成本，benchmark 必须计入。

把现有验收 work digest 原样抽出，供验收和自查依据失效共同复用，避免第二套
工作身份规则或循环导入。更大的 Goal 迁移／替代有意留后。Provider 复用既有
canonical authority（此处验证 File／SQLite），属内置 Core，不新增公共能力或
Python 决策归属。

## 决定性验收

使用可丢弃、公开安全的 File／SQLite Goal，不能操作正在运行的业务状态。

1. 登记成果及首条要求，关联一条真实存在的 Todo。
2. 同一成果接收第二条合成用户纠正；原始 Goal、成果目的和旧要求逐字保留。
3. 重启调用方并切换工作；正常工作前读取仍显示两条要求及原始来源。
4. 关联 Todo 完成而某条要求未满足时，不得接受成果，续行仍展示缺口。后续
   独立检查通过证据由既有验收产生；默认有据自查只能结清规划缺口。
5. 拒绝要求丢失、旧 ID 改文案、跨 Agent 修改、不存在任务、过期 CAS 与冲突
   重试；相同操作只写一次。
6. 对比支撑成果缺失、未确认、未满足和已满足前后的研究准入：根状态、配额／
   停止决定、下一项可执行工作保持；另测 blocked／deferred 的合法等待。
7. 打包 Goal UI 连接真实后端，完成读取、细化、重载、过期恢复和桌面／窄屏
   检查；验证没有成果的 Goal 行为保持。

这些验证证明产品语义和恢复，不证明真实模型识别、安装宿主采用、质量增益或
人工注意力下降；测试数量与 PR 合并均不能替代后者。
